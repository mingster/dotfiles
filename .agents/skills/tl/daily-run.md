# Daily run (scheduled at 07:49 Asia/Taipei, or `/tl daily run`)

Loaded by the Tech Lead for `/tl daily run` only. Follow `.claude/agents/tech-lead.md` for everything it does not say.

Teammates spawn only in an interactive Claude Code session. A run started with `claude -p`, the Agent SDK or a desktop scheduled task has no team: do the run in the mode in `.agents/skills/tl/other-tools.md` and say so under **Now**.

Start each run in a new session, never with `--continue` or `--resume`: yesterday's context is in the PRs, issues and task list, not in the conversation. The daily run gets the team working; it is not only a report. Do the steps in order and send one message at the end.

1. **Digest.** Run `bin/sql/morning-digest.sql` against `RIBEN_AGENT_RO_URL`. Hand each abnormal line to its owner: open tickets and contact messages to support-csm, failed charges and ledger anomalies to secops-finops, cron, backups, hosts and errors to qa-sdet, a drop in signups or a rise in cancellations to sales-marketing. Anything that broke becomes an `incident` issue (or a comment on the open one) before step 2.
2. **Triage.** For each issue labelled `needs-triage`, read it and the code it names, then replace the label: `ready-for-agent` (enough detail, not gated, contradicts nothing), `ready-for-human` (needs an owner decision; comment the question with your recommendation), `needs-info` (comment what is missing). A product change needs an intent: spawn architect-pm to draft it and label the issue `ready-for-human`. A bug without a P label goes to architect-pm to rate.
3. **Issue budget.** Apply the Issue budget in the root `AGENTS.md`. Close duplicates (comment `Duplicate of #N`), issues a merged PR already fixed, and issues about code that no longer exists, each as not planned with a one line reason. Fix label drift: `ready-for-agent` on an issue whose body says it is blocked, `blocked` with nothing named. While a repo is over 30 open, move issues with no PR and no activity for 7 days onto its `backlog` issue, lowest priority first (P3, then P2), closing each as not planned with a link to its line, until it is at 30. Promote a backlog line to an issue only while the repo is under 25. Report it as an **Issues** line under **Now**: opened, closed and net for the last 24 hours, and the open count against 30.
4. **Open team PRs.** No review yet: spawn qa-sdet, plus secops-finops when the diff touches auth, tenancy, rate limits or money. Blocking comments or failing checks: spawn fullstack-dev on that branch (2 rounds, then **Needs owner**). A merge conflict with `main`: fullstack-dev merges `main` into the branch, never force pushes. No blocking comments and green checks: merge it (see Merging).
5. **Pipeline.** After the merges, spawn release-manager to run `/deploy local` on `origin/main`, then `/deploy staging` if it passed. When staging has passed its smoke check and is ahead of production, release-manager deploys it under the standing go and you list it on the **Deployed** line; only what the standing go does not cover goes under **Needs owner** as `Ready for owner to approve production: <sha>, <N> PRs`. A failed stage goes in the report with its error and the issue opened for it.
6. **New work.** While fewer than 10 team PRs are open, pick up to 3 `ready-for-agent` issues with no open PR. Order: `hotfix`, then `incident`, then titles starting `Security:`, then `bug` by P label, then the rest, oldest first. At 10 or more open, start nothing new and say so.
7. **Weekly, on Mondays.** Also ask support-csm for the 用戶滿意度與常見痛點報告 and sales-marketing for the combined commercial and growth report, and put the top findings under **Now**.
8. **Report.** One message in the three part shape, with a **Merged** line under **Now** (each PR merged since the last run as number and title) and a **Deployed** line (the commit now on local, staging and production) and the **Issues** line from step 3.

Never in the daily run: deploy production outside the standing go, roll back, write to production data, message a customer or store, close a ticket, or close an issue as completed without a merged PR (closing as duplicate, already fixed or moved to the backlog under step 3 is allowed). No personal data in the report.

## Executive and commercial reporting

Send the completed daily run report directly to Elon (`elon`). On Mondays, include qualified pipeline, wins and losses, paid conversions, revenue evidence, experiment results and the next three growth bets in `sales-marketing`'s combined commercial and growth report, alongside the analytics comparison and explanation of changes. Include its findings in the existing report format. Routine specialist delivery and support reports go to the Tech Lead (`lead`), which consolidates them for Elon. Sales reports commercial outcomes to CEO; SecOps reports independent material risk to CEO and technical findings to lead. Keep critical/suppressed-concern escalation open. Owner-facing reports may use Taiwan Traditional Chinese or English without mirroring the owner.
