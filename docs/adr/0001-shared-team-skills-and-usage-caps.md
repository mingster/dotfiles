# Shared team skills and usage caps

Status: Accepted  
Date: 2026-10-06

The agent team skills (`elon`, `ceo`, `crew`, `tl`, `deploy`) were copied by hand into each project and drifted apart. The usage gate (a cap on AI usage per provider) was only a written rule in the role files, so nothing stopped a worker from starting when a provider was out of quota.

## Decision

1. **Three tiers of skills.**
   - General skills (for example `orchestration`) live only in `~/dotfiles/.agents/skills` and are linked into `~/.claude/skills` and `~/.agents/skills`. A project does not copy them.
   - Team skills `elon`, `ceo`, `crew`, `tl` and `deploy` have one source, `templates/agent-team/.agents/skills`, product neutral. `script/setup-agent-skills.sh` links them on each machine to the dotfiles checkout, `script/agent-team.sh sync` removes any older copy from a project, and `agent-team.sh check` reports a Tier 2 copy or link left in a project as drift. Project facts live in the project: `docs/agents/team-facts.md` and `docs/agents/deploy-facts.md`.
   - Project skills stay in the project's `.agents/skills`, with links from `.claude/skills` and `.cursor/skills`.
2. **Machine links, not project copies, for team skills.** A project holds no copy of a Tier 2 skill, so a copy cannot go stale. A machine without `~/dotfiles` does not have the skills. `agent-team.sh check` flags a copy that reappears in a project.
3. **The usage gate is enforced by a hook.** `script/usage-gate-hook.py` (PreToolUse on Bash) runs `usage-gate.py check` for every `orca orchestration worker-start` of a claude, cursor or antigravity worker, and denies it when the provider's ceiling is reached (see point 4). The check holds back a reserve for each worker already running on that provider (`orca orchestration worker-list`, across every Run): 2 points for a strong model, 1 for any other. A start is refused a little before the ceiling, so running workers keep room to finish. Elon and the Tech Lead then pick the next provider in the fallback order.
4. **The thresholds are owner reserved and live in one file.** `script/usage-gate.config.json` holds the ceilings (Claude 95, Cursor included pool 100, each Antigravity pool 95), the reserve weights and the missing reading rule. `check`, `pick` and `fleet-watch.py` all read it. The daily cap is what is left under the ceiling at the start of the day, divided by the days left until the provider's reset (a partial last day counts as a fraction). `--cap N` still fixes it. Agents do not change these values.
5. **The daily cap blocks automatic starts only (owner 2026-11-13).** A start is automatic when the caller passes `--auto` to `check` or `pick`. `fleet-watch.py` passes it for the issue scan and for babysit. An automatic start past the cap is blocked until local midnight. A manual or coordinator start never is: it is allowed with the note "pacing: prefer a lighter model".
6. **A missing reading falls back to the last good one (owner 2026-11-13).** The gate keeps the last fresh reading of each provider. When no fresh reading can be had, that reading is used if it is under 2 hours old and at least 10 points under the ceiling, and the start is allowed with a note. Otherwise the verdict is unknown (exit 4) and the start is blocked. Antigravity with no reading at all is allowed in `check` and in `pick` alike (owner 2026-11-12); the worker stops at its first quota or sign in error.
7. **`pick` ranks by pace (owner 2026-11-13).** Roles other than `fullstack-dev` and the light tier rank providers by headroom per day left until the provider's reset, so quota about to reset is spent first. The builder roles keep the fixed order: Cursor Grok, then Claude, then Antigravity. Strong roles never run on Cursor.
8. **Refusals are visible (owner 2026-11-13).** `fleet-watch.py` writes one `usage_gate_refused` line to `fleet-watch.log` per refused provider and pass (provider, verdict, reason, reading age). After 30 minutes of refusals while the refused provider has more than 20 points of headroom, it sends the coordinator one notice, not one per pass. Usage counts for the whole account, including a person's own app sessions.

## Consequences

A fix to a team skill is made once here and reaches every machine through its link into the dotfiles checkout. A copy placed in a project is flagged by `agent-team.sh check` and removed by `agent-team.sh sync`, so project specific facts go in the facts files. The gate fails closed: a provider with no fresh reading and no usable last good reading is blocked, except Antigravity, which starts blind. The gate reads Antigravity per model pool from its local language server; Cursor reads its billing cycle usage. The hook lives in `~/dotfiles`, so a machine without dotfiles is not gated. The gate checks only at `worker-start`; a running worker is never stopped. "Used today" is the whole account's cycle percentage now minus its value at the start of the local day (Claude: the first statusline reading of the day; other providers: the first reading the gate saw that day), so a provider's own app sessions outside Orca count against the cap.

Amended 2026-11-13 (issue 987): points 3 to 8 replace the earlier text, which said a missing reading was allowed with a warning, that the daily cap denied every start, and that the reserve was 1 point per worker.
