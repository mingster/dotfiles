### Workflow translation and all teammate responsibilities

The stage map remains [our SDLC map][sdlc]. Poteto routing becomes brief selection; design prototypes support Grill and Spec; multi phase plans become Tickets; bug and feature playbooks support existing diagnosis and TDD during Build; verification, babysit and shipping support Review and lead integration. Session pickup and cleanup surround those stages. This is a translation, not permission to bypass accepted specs or merge gates.

| Teammate and existing role source | Decision to carry into its existing role or brief |
| :--- | :--- |
| [Elon][t-elon-role] | Own the owner interface and resolve business authority; send the lead a finite outcome, proof and boundaries. Inspect concise decisions rather than absorb worker logs. |
| [Tech Lead][t-lead] | Author briefs, dispatch engineering, reconcile every child, own integration and publication. Delegate code and independent reviews, restore the exact child worktree path and retain open rulings across rotation. |
| [Architect PM][t-pm] | Write falsifiable acceptance criteria and domain boundaries; use bounded prototypes for unknowns. Accepted intent, spec and ADR decisions remain outside worker authority. |
| [Fullstack Developer][t-dev] | Implement one verifiable unit at a time with TDD; obey the brief's exact verification scope and forbidden commands. Commit locally and return evidence to the lead. |
| [QA SDET][t-qa] | Independently inspect bounded slices at a full SHA; aggregate complete coverage before approval. Match evidence to the real surface and record blocked checks explicitly. |
| [SecOps FinOps][t-sec] | Apply boundary and domain principles to security, tenancy and financial evidence. Keep read only investigation distinct from authority for money movement or production changes. |
| [Release Manager][t-release] | Require deploy stage, release SHA, actual host evidence and owned process cleanup. Source tests cannot substitute for smoke or provider proof. |
| [Sales Marketing][t-sales] | State the metric, source and expected user outcome; test self serve assumptions with existing evidence. No implied authority for outbound, spend, pricing or publication. |
| [Support CSM][t-support] | Turn symptoms into redacted reproduction evidence and draft clear customer language. Sending a customer response still requires the role's existing permission. |

All role bodies must work in Codex and Claude. Frontmatter tool names do not create Orca permissions. R [model routing][r-routing] remains authoritative for provider, model family, capacity and browser capability. The installed [orchestration skill][orca-skill] supplies runtime commands through `orca skills get orchestration`; there is no `T/.agents/skills/orchestration/` to copy or modify. [Adoption script][adopt-script] explicitly obtains general skills globally.

The [token budget source][t-budget] also contains older wording about a stopped worker pushing and Claude forked subagents. Reconcile those sentences with local commits and Orca dispatch in the same rollout, without altering any numerical budget or stop. A context token threshold and a worker turn threshold are separate controls.

### The 24 steering cues and the decision each should change

These are proposed applications, not claims that every principle changed this study. Each name links to its original full rule. Put the compact vocabulary in a single on demand reference, proposed `T/docs/agents/decision-principles.md`; task briefs carry only relevant cues. Reports say “I chose X because Y, evidence Z” rather than enumerate principles. Our scopes, strike rules and owner gates override any broader source advice.

| Source principle | Decision changed in our team |
| :--- | :--- |
| [Laziness protocol][pr-laziness-protocol] | PM and developer choose the smallest complete change, including deletion, before adding machinery. |
| [Foundational thinking][pr-foundational-thinking] | Architect PM settles the central data shape and executable scaffold before feature logic. |
| [Redesign from first principles][pr-redesign-from-first-principles] | Architect PM changes a boundary coherently when evidence warrants it, through an accepted design change rather than worker scope expansion. |
| [Attack the premise][pr-attack-the-premise] | Developer names and tests the shared premise after two failed fixes only if existing strike limits still permit work; a hard stop remains a stop. |
| [Subtract before you add][pr-subtract-before-you-add] | Developer removes proven dead paths before building on them, inside the allowlist. |
| [Minimize reader load][pr-minimize-reader-load] | Lead sends one self contained brief and reviewers read bounded evidence rather than conversation history. |
| [Outcome oriented execution][pr-outcome-oriented-execution] | PM defines a migration finish predicate; intermediate compatibility is deliberate and scoped, not an excuse to override test limits. |
| [Experience first][pr-experience-first] | Support, growth and QA judge the actual user flow, useful content and affected store kinds. |
| [Exhaust the design space][pr-exhaust-the-design-space] | Architect PM compares a few bounded prototypes for costly unknowns, instead of debating or multiplying routine designs. |
| [Build the lever][pr-build-the-lever] | Lead commissions a reusable command for repeated verification instead of repeating manual work in each worker. |
| [Model the domain][pr-model-the-domain] | Architect PM and SecOps encode ownership, money and lifecycle states explicitly rather than scatter flags. |
| [Boundary discipline][pr-boundary-discipline] | Developer and SecOps validate external and tenant boundaries once at the correct seam, retaining required defense checks. |
| [Type system discipline][pr-type-system-discipline] | Developer makes illegal domain states unrepresentable and removes unsafe assertions instead of hiding invalid data. |
| [Make operations idempotent][pr-make-operations-idempotent] | Release and developer reconcile actual state before retrying; uncertain remote money state cannot justify another write. |
| [Migrate callers then delete legacy APIs][pr-migrate-callers-then-delete-legacy-apis] | Developer proves caller coverage before deleting an internal API; public consumers and staged releases require explicit compatibility planning. |
| [Separate before serializing shared state][pr-separate-before-serializing-shared-state] | Lead gives each writer an isolated worktree and file ownership before inventing locks. |
| [Prove it works][pr-prove-it-works] | QA and release demand evidence on the relevant artifact and environment, not a proxy pass. |
| [Fix root causes][pr-fix-root-causes] | Developer traces the reproduced failure to the first invalid state before applying a workaround. |
| [Sequence verifiable units][pr-sequence-verifiable-units] | Lead chooses independently verifiable slices and developer checks each before stacking more work. |
| [Test behavior, not implementation][pr-test-behavior-not-implementation] | QA asserts observable outputs and side effect counts rather than mirror helper implementation. |
| [Explain the number][pr-explain-the-number] | Growth, QA and release report comparable inputs, run count, range and limiting factor before claiming improvement. |
| [Guard the context window][pr-guard-the-context-window] | Lead delegates bulk inspection to fresh Orca workers and receives compact findings plus artifact pointers. |
| [Never block on the human][pr-never-block-on-the-human] | Every teammate resolves reversible uncertainty within standing authority; reserved decisions follow the lead to Elon. |
| [Encode lessons in structure][pr-encode-lessons-in-structure] | Team audit selects a guard that rejects a real repeated failure before adding another instruction. |

### Rollout and acceptance gates

1. Rebase the implementation plan onto audited `788c067` and inspect its final three role files. The current document proposes followups only; it does not edit that branch. Retain the restored child worktree path as an explicit acceptance check.
2. Build focused failing regressions at the real seam for the chosen increment. For rank 1, demonstrate a denied full suite attempt and permitted targeted check under both providers. For rank 5, distinguish a tooling failure without mutation from a genuine failed repair without weakening existing stop limits. Record baseline and candidate evidence, not just instruction presence.
3. Keep changes in dotfiles sources. Coordinate the same release across dotfiles, riben.life and pstv. [Sync team skills][sync-script] copies only `T/.agents/skills/*`, not role files or owned project contracts. Use it for generated skills, then `--check`; use the [adoption script][adopt-script] `--dry-run --reset` preview and reviewed role diffs for role and routing updates, preserving project customization. Project team docs are missing only there, so reconcile the live Delivery contract explicitly. Do not claim a skills sync updated every role.
4. Run the focused existing [team tests][team-tests], [audit tests][audit-tests] and relevant script checks named by the implementation brief, including [ShellCheck entry point][shellcheck] for shell changes. Verify root AGENTS files stay below 200 lines and CLAUDE remains a pointer under [agent file convention][agent-files]. Keep detailed vocabulary and audit inventory in on demand docs.
5. Lead publishes only after current full SHA review, cross family review where required, synchronized generated skills and rollout evidence. Elon remains the only owner contact. Deploy, external messaging, database changes and spending retain their own gates. Nothing in this study authorizes publication or changes token budgets.
