# Fleet watchdog

Run `python3 script/fleet-watch.py --config <private-json> --state <private-state>` once each minute from a supervisor independent of the coordinator's inbox waiter. Configure `runs` with each run's `id`, `terminal` (coordinator handle) and `waiter_pattern` (a process pattern unique to that run); configure `host_caps` using the host IDs returned by worker-list. Keep handles and machine names in the private config, never in this repository.

A waiter absent across ten minutes of observations with unread deliveries gets one terminal wake, then rearms when the waiter returns or the inbox clears. Failed dispatches get one alert each. Every nonfinal dispatch, including children, counts toward host capacity. The watchdog only alerts; the coordinator follows Orca recovery before stopping or retrying anything. A CLI failure preserves state and fails the pass so the supervisor can report it. Without an independent minute scheduler this is an unactivated guard, not liveness coverage.
