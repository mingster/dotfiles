name: wrap-up
description: Clean finished branches, worktrees and ended Orca panes at the end of a session, after a batch of merges, or before a release.

# Wrap up

Run in the repository being cleaned. Requires Git, gh and jq; sign in to gh for PR status checks.

1. Run `~/dotfiles/script/wrap-up.sh --fleet --repo "$PWD"` to preview cleanup on this host and every fleet host. Dry run is the default and uses existing `origin/main` refs while previewing the fetch. Read every proposed deletion and the kept list.
2. Once cleanup is authorized by the coordinating role, run `~/dotfiles/script/wrap-up.sh --apply --fleet --repo "$PWD"`. This fetches origin, removes eligible clean worktrees, prunes worktree metadata, deletes finished local and remote branches, closes finished Orca terminals on the local host and every environment `orca environment list` shows (a terminal of a completed, failed, cancelled or released dispatch, one whose process exited, or one with no agent on a worktree path where every dispatch is settled, such as a shell or a worker-pane.sh pane; never your own terminal, a live dispatch's, one running an agent, a `lead-` worktree's, or a terminal on a path with no dispatch, which is reported as unknown owner; only the newest 200 dispatches per host are read), closes ended Orca panes (a settled worker whose worktree still exists only when it was released with `worker-pane-close.sh --release`, so release every validated worker that way), deletes Chrome `code_sign_clone` dirs (macOS per-user temp, about 750M each) and agent temp files (stale scratch session dirs, throwaway Chrome profiles, loose `NNNN-*.log` and `.sh` files) that no running process holds open, and fast forwards a clean main checkout. Remote deletion is a push, so workers whose role prohibits pushing report the preview to Elon for application.
3. After apply, report the `Stale (needs a decision)` section to the owner, one line each (branch, age, first commit subject). Stale branches have unmerged commits, no open PR, a last commit older than 24 h and nothing running in their worktree; `--apply` never deletes them. On the owner's yes, run `~/dotfiles/script/wrap-up.sh --apply --stale --repo "$PWD"`, which deletes them local and remote.
4. Read the final counts and kept list. Report dirty, active, protected and unmerged entries with their reasons; preserve work that still needs attention.

`--fleet` also runs the cleanup over ssh on each host in `script/wrap-up-fleet.config.json` (untracked; copy `wrap-up-fleet.config.example.json`, entries `{host, repo_dir}`). A fleet host removes finished worktrees and finished local branches (with or without a worktree) under the same keep rules, plus a keep for any worktree a process is running in; it never deletes origin branches, closes terminals, removes temp files or fast forwards a checkout, since this run does those once. Output is grouped per host with the same counts line and ends with a fleet total. An unreachable host only warns. Allow up to `WRAP_UP_FLEET_TIMEOUT` seconds per host (default 900).

The script protects main, master, staging, production, web2 branches, staging and production suffixes, and branches checked out in retained worktrees. Any worktree whose directory name starts with `lead-` is kept, even when it holds a merged branch; merge cleanup (`merge-cleanup.sh`, run by `lead-merge.sh`) follows the same rule. A merged commit, a closed PR, or commits that are all patch-equivalent on `origin/main` (squash merges) make a branch eligible; a worktree whose only changes are untracked images (png, jpg, jpeg, gif, webp) counts as clean; an open PR overrides a historical closed PR. Unknown Orca terminal ownership retains its worktree. Terminals are listed as `Close terminal <handle> (<env>, <reason>)` and `Kept terminal <handle> (<env>, <reason>)`, and the counts add `terminals closed=N kept=M`; closed terminals no longer hold their worktree, so the same run can remove it. When Orca is unavailable, the script warns that the active dispatch check was skipped; resolve that warning before applying if workers may still be running.

Temp items are listed as `Remove temp <path> (<size>, <reason>)`; the last line gives `temp removed=N kept=M bytes=B`, so report the bytes freed after apply. An item goes when its worktree is gone or nothing in it changed for 24 h; the current session's scratch dir and the inbox waiter files (`~/.local/state/agent-team/elon-wait.sh`, `elon-waiter.json`) are kept. The full inventory is `docs/agents/wrap-up-temp-files.md` in dotfiles.

Chrome clones are listed in the preview as `Remove Chrome clone <path>`. A clone any process holds open (checked with lsof) is kept and reported; when lsof is missing, all clones are kept.

Completion means the cleanup counts and every retained item have been reviewed and reported to the coordinator.
