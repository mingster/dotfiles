# Agent team

{{PROJECT_NAME}} is run by its user and an AI team: the coordinator (CEO) and specialist roles. The user talks to the coordinator, who delegates and contacts the user only for decisions it cannot make. Role files live in `.claude/agents/`; this file lives once in `~/dotfiles/templates/agent-team/docs/agents/team.md`, and project differences go in `docs/agents/team-facts.md` only (deploy facts in `docs/agents/deploy-facts.md`).

This file holds only facts and the rule table. GitHub issues and PRs are the state of record.

| Role | File | Primary output |
| --- | --- | --- |
| The coordinator (CEO) | `elon.md` | Priorities, user contact, dispatch |
| architect-pm | `architect-pm.md` | One document per feature (intent, spec and units), issue triage, weekly list |
| fullstack-dev | `fullstack-dev.md` | Isolated branch with its own tests. Cursor `grok-4.7-xhigh`; Claude only when that quota is out |
| qa-sdet | `qa-sdet.md` | Verifier Verdict (`script/post-verdict.sh`), Playwright runs, weekly swarm live lanes |
| secops-finops | `secops-finops.md` | Money and auth PR reviews, weekly reconciliation |
| support-csm | `support-csm.md` | Ticket triage, reply drafts and recurring pain points |
| release-manager | `release-manager.md` | Staging in the daily program (`daily-run.md`), production and rollback per Gated actions (a production rollback is a production deploy) |
| sales-marketing | `sales-marketing.md` | Positioning, acquisition plans, growth experiments, weekly numbers |

| Severity | Meaning | Action |
| --- | --- | --- |
| P0 | Critical security, financial or production outage | Hotfix immediately; involve SecOps |
| P1 | Core workflow broken without a workaround | Hotfix immediately |
| P2 | Issue with a workaround or limited impact | Normal queue |
| P3 | Cosmetic or wording issue | Normal queue |

Usage gate: `usage-gate-hook.py` gates every worker start from Claude Code, Cursor and Antigravity (the last two installed by `~/dotfiles/script/setup-cursor.sh` and `setup-antigravity.sh`). A coordinator starting workers from either IDE first confirms its entry is installed, else runs in Claude Code.

Before judging engineering reviews or tests, the coordinator reads `~/dotfiles/templates/agent-team/docs/agents/engineering-integration.md`. Release failure classification follows `.agents/skills/deploy/SKILL.md`, Test noise.

## Rule table

Enforcer "none" means only the agent's reading holds the rule.

| Rule | Enforcer |
| --- | --- |
| **No bottleneck:** nothing waits on the coordinator or the user. Each step (labeling, dispatch, verifier, rebase, merge, worker release) runs automatically or by its owning role, with a written default if nobody answers. Only Owner pauses wait on the owner, and only at their merge, send or deploy step; the coordinator sends the owner one batched list. A worker never ends its turn waiting: it asks, names its default and proceeds on it. A step that still needs the coordinator is a bug: file it. | none (code gaps: #1016, #1017) |
| **Owner pauses:** exactly these wait on the owner ("owner-reserved"): money rules and prices; spending and contracts (paid overage, new paid services, budget, legal); each customer message draft; irreversible data deletion; production deploy once a real store is live; one look at a new feature or page (screen or screenshot) before production, which the owner can stop. Role file and hook changes, weekly update PRs and new feature builds need no owner approval unless they loosen a safety limit (production access, data deletion, secrets, payment). | none |
| **The Algorithm:** apply `principle-the-algorithm` before any new rule, step or check. The PR names the requirement it questioned and what it deleted. | none |
| **User decisions:** pricing, legal, production and irreversible data are never declined by the team, only pushed back to the user with evidence. | none |
| **Plan approval:** the user approves prices and money rules before build; new features and pages follow Owner pauses. The coordinator decides the rest and records it on the issue. | none |
| **Pre-build grill gate:** a multi role grill runs only for money (payments, billing, refunds, ledger, credits, pricing or entitlements) with secops-finops, architect-pm and the coordinator, and for new UI pages with sales-marketing and the coordinator. The coordinator approves grill results, except money rules and prices: there the build runs to a green PR with a Verdict while the owner reviews the grill result, and only the merge waits. The hook reads the title, body and labels of every issue the spec names. A match on price, pricing, fee, refund, payment, pay, subscription, plan, discount, coupon, wallet, credit, billing, invoice, money, ledger, entitlement, or the Chinese 價格, 價錢, 付款, 退款, 儲值, 訂閱, 方案, 折扣, 優惠, 點數, 金流, 發票 or 費用 keeps the gate. The record is one line, `Grill approved: coordinator YYYY-MM-DD`, `Grill approved: owner YYYY-MM-DD`, or `Grill approved: elon YYYY-MM-DD`. `grill_approvers` in `.claude/hooks/guard-config.json` names more logins. Every agent posts as the owner, so that check is a speed bump against a missing or mistyped line, not proof of who wrote it. `Elon take over` uses the same author check. | `.claude/hooks/guard-bash.py` (grill check on build worker starts) |
| **Role changes:** a change to a role definition (`.claude/agents/`, other provider role files, canonical role templates) or a hook merges on a passing non-author Verdict with the coordinator's approval, listed to the owner weekly. A change that loosens a safety limit needs the owner's explicit approval of the concrete diff; silence, QA PASS or Checks PASS is not approval. Each commit carries `Owner-approved: <approver> <date> (<where approved>)`. When a change to an owner-gated file only copies rules the owner already approved, the coordinator may add the `Owner-approved:` trailer, citing the source decisions (issue or PR numbers and dates) in the commit and PR body; a new rule or a loosened limit still waits for the owner. | `script/team-audit.sh` (flags commits from 2026-11-03 without the trailer), `script/ship.sh` |
| **Gated actions:** only the user approves messages to customers, partners or the public, closing customer tickets, refunds, credits, discounts, coupons, subscription changes, production data writes, direct production server access, production deploys and rollbacks once a real store is live (before that, either runs after the Playground regression passes), spending, force pushes, and accepting or rejecting an intent or spec on money rules or prices. release-manager may push the production branch with no owner go only after `git fetch origin main` and `git show origin/main:docs/agents/deploy-facts.md` in the repo that loaded the guard. The file needs one unindented line, `* Production data: production holds only test data`, outside a code fence or an HTML comment, and no line may say a real or live store exists. A failed fetch keeps the go. So does `cd`, `git -C`, `--git-dir`, or a URL remote aimed at another repo, and so does a force push. | `.claude/hooks/guard-bash.py` (production push, force push, approval scope); none for the rest |
| **Orca dispatch:** dispatch only through Orca orchestration; the in flight count comes from the fleet caps and the usage gate. | `script/usage-gate.py`, `usage-gate-hook.py` |
| **Allowed scripts:** "call no scripts" bans ad hoc coordination scripts only. The usage gate, `heavy-gate.sh`, `ship.sh` and worker-watch stay. | `.claude/hooks/guard-bash.py` (un-gated heavy jobs) |
| **Publication:** one owner per PR. It writes the branch, carries it through rebases and fix rounds, and lands it with `ship.sh` on a PASS Verdict at the current head from a non-author verifier. The coordinator does not merge by hand; fleet-watch auto-ship backs up a verified PR whose owner has settled. | `script/ship.sh`, `script/team-audit.sh` (merge wording) |
| **Stall detection:** stays on worker-watch. | `~/dotfiles/.agents/skills/orca-team/worker-watch.sh` |
| **Child ledger:** the coordinator keeps a ledger row for every child (task ID, dispatch ID, terminal, worktree, branch, full head SHA, state, next actor, evidence path). | none |
| **Background waits:** every wait runs in the background with a timeout; in Claude Code as its own Bash call with `run_in_background: true`, never a shell `&`. | `.claude/hooks/guard-bash.py` |
| **No run-use for workers:** workers and child coordinators never run `orca orchestration run-use`. The coordinator rebinds with `run-use --id <run>` after a restart. | none |
| **Release settled workers:** every settled child, including FAILED, gets `worker-release` and its ended panes closed. | `script/wrap-up.sh` |
| **Redesign:** a PR whose Verdict or Review failed twice gets `needs-redesign` and no third patch. The coordinator closes it, commenting what both failures showed, and dispatches a fresh worker whose new brief restates the goal from first principles and names both lessons. The owner is asked only if the redesign also dead ends. | `script/pr-review.sh` |
| **Extra Strong review:** extra Strong cross review only for money transactions, or when the coordinator or the user asks for it on that issue. | `script/pr-review.sh` (money paths) |
| **Merge host:** `ship.sh` runs on the coordinator's host; a PR owner on another host leaves its verified PR to fleet-watch auto-ship. | `script/worker-startup.sh` |
| **Board status:** every worker's Finish runs `orca worktree set --worktree active --workspace-status in-review` before `worker_done`. A release with no PR sets `completed`, and `ship.sh` sets it after a merge. | `script/brief-lint.sh` (Finish must say so), `.agents/skills/orca-team/worker-pane-close.sh`, `script/ship.sh` |
| **Database head checks:** a head check with a database step runs on the database host, never one without Postgres. `createdb: command not found` is a host fault, not a pass. | `script/head-checks.sh` (`head_checks_remote`) |
| **Antigravity login:** after starting an Antigravity worker, read its screen. A login prompt still shows ready and live. | none |
| **Reach a remote worker:** send to a worker on another host with `orca terminal send --environment <env>`, never `orchestration send`. | none |
| **Acceptance checklist:** a brief's Acceptance is a `- [ ]` list the builder copies into the PR body with proof beside each box: a file path, a command with its output line, or `n/a: <why>`. A behaviour item is proved on the real artifact (live run or screen), not only a unit test, and a test the builder adds or tightens runs across every variant it covers (locales, views). A box without proof is not done. | `script/brief-lint.sh` (Acceptance present); none for the proofs |
| **Verdict:** a PASS Verdict includes `Command: <exact test command run>`. The verifier is a different model family from the builder (Claude, GPT, Grok, Gemini; sonnet and opus are one family). It walks the Acceptance list and FAILs naming each unproved item; the rework fixes only those. The Verdict judges the brief, not taste: extras become a follow up issue. Never edit or minimize a Verdict; post a new one. | `script/post-verdict.sh`, `script/ship.sh` |
| **Verdict carry:** a PASS survives a rebase when the `git patch-id --stable` of `merge-base(origin/main, head)..head` matches the Verdict head. | `script/ship.sh` (`verdict_carry`) |
| **Wording only after a Verdict:** when the Verdict head differs from the head, `ship.sh` merges on green checks with no new Verdict if every file changed between them is `.md` under `docs/` or `changelog.d/` or at the top level, the diff adds no code fence, and no changed path is protected (`script/lib/protected-paths.sh`). Anything else keeps the patch-id rule. | `script/ship.sh` (`wording_only_carry`) |
| **Head checks:** proving commands include every `.agents/head-checks.conf` command for the changed files, with `shellcheck --severity=error` on each changed `.sh`, once, at the head. | `script/head-checks.sh` |
| **WIP cap:** at most 6 open PRs per project; at 6, start no new feature unit (test fix, hotfix and user UI look PRs exempt; owner-reserved PRs count). Besides seats and the usage gate it is the only limit on starts: a free seat and a `ready-for-agent` issue mean start now. | `script/fleet-watch.py` (issue scan starts on a free seat) |
| **One PR per fix batch:** fixes from one regression run or failing area go in one PR. | none |
| **Copy at the spec:** the spec and each unit carry the exact new strings in tw, en and jp; reviewed with the spec and shown in the owner's look before production. | none |
| **Native copy:** `en` is fluent American English and `jp` natural Japanese, never word for word from `tw`. A menu or button name quotes the real label in that locale's file. | none |
| **New UI page:** the owner's look before production uses phone screenshots of the design or prototype, stored in `~/.claude/state/screenshots/<repo>/<issue>/`. | none |
| **Straight to staging:** release-manager promotes trunk to staging after merges. Production follows Owner pauses. Japanese homepage copy needs a native reader before launch. | none |
| **Heavy jobs:** Playwright and production builds run through `~/dotfiles/script/heavy-gate.sh --weight 2`; a long regression sets `HEAVY_GATE_CLASS=long`; full `tsc` uses `--measure`. Only the coordinator runs `hw-probe.sh --calibrate`. | `.claude/hooks/guard-bash.py`, `script/heavy-gate.sh` |
| **Strikes:** follow the project's token budget and strike rule in `AGENTS.md`. | `.claude/hooks/strikes.py` |
| **Zero secrets:** never print env files, secrets or keys to output or markdown; never open a secret file with a printing command. | `.claude/hooks/guard-bash.py` (secret readers, `.env` copies) |
| **Messages that name the owner files:** to mention the owner approval file or script in a GitHub or Orca message, write the message to a file with the Write tool and send it with `--body-file`. | `.claude/hooks/guard-bash.py` (text guard) |
| **Push an explicit branch:** `git push origin HEAD:refs/heads/<branch>`, never a bare `git push`. | `.claude/hooks/guard-bash.py` (push to a protected branch) |
| **Close browsers:** a worker that starts a browser with its own debugging port stops it by PID before `worker_done`. | `script/wrap-up.sh` |
| **No substitute tooling:** never replace a team mechanism (Orca orchestration, GitHub Actions, hooks, gates, deploy scripts, worker lifecycle) with self built tooling without the coordinator's approval (the owner's when it loosens a safety limit). | none |
| **One unit, one session:** start a fresh session for a new unit; keep `active_run.md` current for long tasks. | none |
| **Own your files:** isolated branches and worktrees; no concurrent edits to one file. | none |
| **Same-file rule:** never two open PRs or two started issues on one file. Before filing, search open issues and PRs for the touched files. An unstarted issue absorbs the new work (edit its body, close the new one). One being built gets the new issue as a GitHub blocked-by; issue scan skips blocked issues, so it starts on fresh main after the first merges. | `script/fleet-watch.py` (`issue_scan_blocked`) |
| **Issue budget:** search before filing (`gh issue list --search`); an issue names the change, an observable done condition, the requirement owner, a `Deleted:` line and the owner role; a bug carries its P label. When `script/brief-lint.sh` passes on the body and the work is not owner-reserved, the filer adds `ready-for-agent` and a P label (default P2, where the repo has them) in the same create, in the repo whose files change (one linked issue per repo). Never label an issue a worker is already doing. A small PR finding is fixed in that PR, otherwise one follow up issue per PR. | none |
| **Labels:** `blocked` names what and who it waits on and never sits with `ready-for-agent`. `needs-triage` never sits with `ready-for-agent` either: adding one removes the other. architect-pm owns `needs-triage` and rewrites and labels an issue untouched there for 2 hours. `ready-for-human` is only for owner-reserved work. | `script/team-audit.sh` (labels) |
| **Process findings:** log them with `~/dotfiles/script/team-audit.sh --log "<finding>" "<evidence>"`. | `script/team-audit.sh` |
