# Daily program kickoff

The `daily-program-1900` Orca automation wakes the coordinator daily at 19:00 Taiwan time, saying whether staging is behind `origin/main`. Run time, digest query and its read only database URL: the project's `docs/agents/team-facts.md` (Daily run). Spawn each step to its owning role through Orca (`.agents/skills/orca-adapter/ORCA-ADAPTER.md`); do not do their work. It is a schedule, not a gate (`team.md`, No bottleneck). Otherwise follow `.claude/agents/elon.md`.

Take yesterday's state from PRs, issues and the task list, never chat memory. Do the steps in order. Message the user at the end only when a step needs a user decision.

1. **Digest.** Run the digest query and hand each abnormal line to its owner: tickets and contact messages to support-csm, failed charges and ledger anomalies to secops-finops, cron, backups, hosts and errors to qa-sdet, signup drops or cancellation rises to sales-marketing. Anything broken becomes an `incident` issue (or a comment on the open one) before step 2. **Support queue:** take every open ticket, contact message and support email through the support ticket rule in `.claude/agents/elon.md` the same day: fix if needed, support-csm drafts the reply in the customer's language, and the coordinator sends the user the ticket, what was done and the draft. Nothing is sent before the user approves.
2. **Triage.** architect-pm runs the `triage` skill (`~/.agents/skills/triage/SKILL.md`, the coordinator as maintainer, an agent brief on each `ready-for-agent` issue) on each `needs-triage` issue and replaces the label: `ready-for-agent` (enough detail, not gated, contradicts nothing), `ready-for-human` (only an Owner pause, or a step needing the owner's own hands or accounts; comment the question with a recommendation), `needs-info` (comment what is missing). A product change needs an intent: architect-pm drafts it and the issue is `ready-for-agent`. A bug without a P label goes to architect-pm to rate.
3. **Issue budget.** Apply `team.md`, Issue budget. Close duplicates (`Duplicate of #N`), issues a merged PR fixed and issues about code that no longer exists, each as not planned with a one line reason. Fix label drift (`team.md`, Labels). Report an **Issues** line under **Now**: opened, closed and net for 24 hours, and the open count.
4. **Open team PRs.** Report each open team PR's state; start nothing for it by hand (fleet-watch starts verifier and rework, `elon-dispatch.md`). The PR owner takes its fix rounds (2 rounds, then the coordinator decides or escalates), merges `main` in on a conflict with `resolving-merge-conflicts`, and merges per `team.md`, Publication. Auth, tenancy, rate limit or money diffs get a secops-finops review. A PR stuck with nobody acting is a fleet-watch bug: file it.
5. **Pipeline.** When staging is behind `origin/main`, release-manager runs `/deploy local` on `origin/main`, then `/deploy staging` if it passed, then qa-sdet runs the pstack `swarm` live lanes on staging (`.agents/skills/orca-adapter/playbooks/swarm.md`) with the journey walk brief in `docs/agents/deploy-facts.md` when it has one. When staging equals main, skip both. When staging passed smoke and is ahead of production: with test data only, release-manager runs the Playground regression and deploys production when it passes (deploy skill, Test data only); once a real store is live, the coordinator asks the user `Ready for owner to approve production: <sha>, <N> PRs. Owner runs: bin/owner-approve.sh promote <sha>`, and release-manager deploys once the user has run it. List it on the **Deployed** line. A failed stage goes in the report with its error and its issue.
6. **New work.** fleet-watch's issue scan starts builders on free seats (`team.md`, WIP cap). Order: `hotfix`, `incident`, titles starting `Security:`, `bug` by P label, then the rest, oldest first. Report how many started; a ready issue with a free seat that did not start is a fleet-watch bug: file it.
7. **Mondays.** Ask support-csm for the satisfaction and common pain points report and sales-marketing for the combined commercial and growth report (qualified pipeline, wins and losses, paid conversions, revenue evidence, experiment results, next three growth bets); put the top findings under **Now**.
8. **Report.** Send the coordinator one message in the three part shape, with **Merged** (each PR merged since the last run, number and title), **Deployed** (the commit on local, staging, production) and the **Issues** line. No personal data.

Run `/team-audit` only when the user says "team-audit". SecOps reports independent material risk to the coordinator; keep critical or suppressed-concern escalation open.

Never in the daily run: deploy or roll back production without the gate in step 5, write to production data, message a customer or store, close a ticket, or close an issue as completed without a merged PR (step 3 closures are allowed).
