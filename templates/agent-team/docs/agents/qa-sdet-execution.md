# qa-sdet execution reference

## Execution
- Before installs/builds run `df -h /`; stop on low disk. Never move dependencies/worktrees to temp.
- **Verifier contract:** on the exact head SHA, read the code and the `head-checks.sh` Checks receipt, which must be PASS (a red one stops the line). Do not run tests, tsc or lint, nor `script/checks-local.sh` when GitHub Checks are green at the head. Run a live browser check (at a phone viewport) only when the diff touches UI files (pages, components, locale copy); other PRs get the full diff audit against the spec plus the tests in the Checks receipt (and a real script or API run when the diff changes one), and the Verdict states why no live check ran. Walk the Acceptance list per `team.md`, Verdict; a proof you cannot reproduce counts as unproved. Docs only PRs use `head-checks.sh`'s doc link check.
- Return `Verdict: PASS|PASS+NOTES|FAIL head=<full sha> verifier=<dispatch id> author=<dispatch id>` as the first line, then what ran and what was observed (or why no live check ran), posted by you as a PR comment. Verifier, author and lead use distinct dispatch IDs. Cover every Unchecked path from the Checks receipt in the verification lane and mention unchecked coverage in the Verdict. When a live check is blocked (host busy, live-check lock held, or DB lock held), wait and retry up to 30 minutes and post no Verdict while waiting; first rerun a failed environment step (install, server start) once, and post FAIL only when the check ran and failed, or after the 30 minute wait limit expires (naming the blocker and the 30 minute wait).
- Auth, tenancy, rate limits and money paths also need an independent secops-finops lane, and both must PASS. Verifier model and provider: `.claude/model-routing.md`; family rule: `team.md`, Verdict. When no other family has quota, a different Claude model is tagged `same-family-different-model`. Never the same agent and model.- Each new head needs fresh checks, except a clean merge of trunk, which carries the Checks PASS and the Verdict (`ship.sh`, `verdict_carry`); an authored or conflict edit needs a new verdict, and a re-verify after a fix checks only the prior FAIL items and the diff since the last verified head. Gate loosening needs the coordinator's current-head countersign.
- **Shared live-check server:** for UI live checks, call `~/dotfiles/script/live-check-server.sh -- <command...>` (or `acquire`, which prints a `LIVE_CHECK_TOKEN` and holds the lock on a one hour lease, then `release --token <token>`), which reads per-host settings from `script/ship.local.json` (`live_check_server`), takes a lock on the live-check host (waiting up to 30 minutes), reuses the one running dev server on latest `main` if it is up (starting it once if not), and releases the lock after without stopping the shared server. Never start and stop a dev server per verifier, and never stop processes by name (`pkill`, `killall`; the guard denies it). If an ad hoc process must be stopped, use `kill` on the pid saved from `$!` in a pidfile or `kill $(lsof -ti tcp:<port> -sTCP:LISTEN)`.
- **Paths:** quote bracketed paths; no escaped paths, `..` or paths outside the worktree; scratch goes in `<worktree>/.scratch/`; temp files never loose in `/tmp`. Heavy jobs use `~/dotfiles/script/heavy-gate.sh` (never a stale `dotfiles-main` path).
