guard-bash now reads the values of literal variables. A command made of `NAME=value` steps, plain statements and at most one trailing `for` loop is checked with each value filled in, so `for h in blueDevil niteking; do ssh $h uptime; done` and `H=niteking; scp /tmp/x $H:/tmp/y` are allowed, while a production host value is still refused by name. A loop over more than 16 words is refused with a request to split it. A script name built from any expansion (`$S`, `${...}`, `$(...)`, backticks, `$'...'`) is matched on the whole path against the blocked scripts, also after shell options such as `-o pipefail`.
