Leads now ask for a worker with `script/fleet-start.sh request`, and one locked `fleet-start.sh drain` starts it under the coordinator's own binding after the host cap, usage gate and grill gate. The start follows the team start rules: the grill gate sees the request's role, the worker starts in the request's own repo from `origin/main` with setup run, a reviewer avoids the author's model family (the request must name it with `--author-family`), a Cursor pick goes through `start-cursor-worker.sh` so its trust marker is written, and a remote start needs the repo's checkout path in the config's `remote_projects`. Refused requests stay queued with their reason in the fleet-watch digest, damaged queue files are set aside or skipped without stopping the drain or the watcher, and a start that may have half happened is never repeated. `fleet-start.sh delay` shows how long requests wait.
