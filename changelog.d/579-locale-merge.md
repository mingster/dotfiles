Lead merge no longer refuses a locale JSON file that main and the PR changed on different keys. When the three way merge is clean and every merged key holds the value of the side that changed it, the project's one line locale check in `.agents/locale-merge-check.conf` (read from main) runs on the merged tree, and a pass accepts the merge. Without that file, or on a failure or timeout, the old refusal stands, and the same key changed on both sides still refuses, including keys holding `null`, `false`, `{}` or `[]`. The check runs once per merge, in the final check after every other refusal, so a PR that is already refused runs none of its code. It runs in a temporary worktree that has no installed dependencies, so a line that needs them fails and the merge is refused. The step and everything it starts is killed on a timeout or a signal, and the worktree is removed on every path. `LEAD_MERGE_LOCALE_TIMEOUT` must be a positive whole number. If main moves while the check runs, the merge is refused. Editing `.agents/locale-merge-check.conf` now needs a Countersign, like `.agents/head-checks.conf`.
