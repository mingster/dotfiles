- `guard-bash.py`: in a project that lists `blocked_scripts`, the guard now refuses to run a command it cannot read. That covers eval, and a program or script name built from `$`, a backtick, a glob, a brace list or a `$'...'` escape, also inside `<shell> -c`, `find -exec`, xargs, `env -S`, the wrappers (after their option values) and a script a shell reads on stdin. The command is read as bash reads it (quotes, comments, backslash newlines, substitutions, heredocs), and a command the reader cannot follow, such as a quote inside `${...}`, is refused. Arithmetic, `case` patterns, `command -v` and heredoc text that feeds no shell are not read as commands. The plain text checks now read `$'...'` without crashing on short escapes such as `\u41`, and a `$'` inside a comment no longer hides the next line. `${X:-word}` and `${#X}` no longer count as a brace pattern next to the secrets dir (#1887).
