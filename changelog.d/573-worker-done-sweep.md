`worker-done-relay.sh sweep`, run once per fleet-watch pass, relays each `worker_done` to its owning lead once and releases the seat only on proof: a builder's branch on the remote at the worktree head, or a reviewer's Verdict for the PR head by that dispatch. It reads the run's mail with `orchestration inbox` (handled and unhandled, nothing marked read), so a waiter that read first loses nothing, and it only sweeps records that have a `kind=` line. A failed send releases nothing and is retried with one digest line. The relay body carries the worker's summary. `worker-done-relay.sh record` writes the owner record atomically (a lead handoff changes only line 1), and `start-remote-worker.sh` and `start-cursor-worker.sh` take `--owner-lead`, `--owner-repo` and `--owner-branch` to write it after the start. `coordinator-drain.sh` drops relayed `worker_done`, no longer writes any file, and with `--wait` checks again when every message in a batch was dropped. The coordinator's waiter command becomes `coordinator-drain.sh --run <run> --wait`. `on-worker-done.sh` writes the reviewer's owner record (`--owner`, default `$ORCA_TERMINAL_HANDLE`).
