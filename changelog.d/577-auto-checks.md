* `on-worker-done.sh` starts `head-checks.sh --repo <worktree> --pr N` detached once the cheap checks pass, so Checks run beside QA without a lead's command and the reviewer start does not wait. One start per repo, PR and head. The marker holds the wrapper's pid: a live pid says already started, a dead pid (finished run, crash, reboot) is cleared and Checks start again. None start when the worktree or PR head moved, the worktree is dirty, or a Checks comment for the head exists; the note says why, including a worktree this host cannot read. A run that ends with no receipt on the PR sends one message to `$ORCA_TERMINAL_HANDLE` through `orca-reply.sh` with the exit code and log path (no handle: the log only, and the start says so). `--dry-run` only prints the command.
* The reviewer marker stores the dispatch id. A repeat call prints that id (or says none was recorded) and names the new `--restart-reviewer` flag, which clears that head's marker and starts one more reviewer. A dirty worktree adds a line to the reviewer brief to review only `git show <head>`.
* `heavy-gate.py`: a playwright job with the default declared memory and a head-checks job never hold slots together, on any host size (tested at 15360, 17408 and 32768 MiB). A browser run started outside the gate is not covered.
