* guard-bash: the "code that starts a process" check ignores text inside one line string literals and comments, so read-only scripts that mention `find -exec stat` or a `"system"` key are no longer denied. Any bare `system`, `exec`, `subprocess` word in code, and any quoted name in code that uses `getattr` or `__dict__`, still counts as a process start. A quoted `cat > file <<'EOF'` body is no longer scanned when an interpreter reads stdin (#1327)
